# 06 · 故障排查

[English](../EN/06-troubleshooting.md) | **简体中文**

先保留未保存内容，再排查原因。涉及文件、配置或恢复记录时，先备份，不通过删除用户数据来重置服务。

## 无法启动

1. 源码部署核对 Node.js 22、Bun 1.3.3，并完成冻结安装和生产构建。
2. 查看终端错误，核对端口是否被占用。
3. 核对[环境配置](03-configuration.md#服务配置)、允许根与运行用户权限。

下载失败时检查网络和证书，不关闭 TLS 校验。远程访问必须配置 HTTPS 来源、非空允许根和绝对服务数据目录。

## 登录失败或会话失效

- 没有密码：按[部署说明](01-deployment.md)在服务设备初始化；没有默认密码。
- 忘记密码：停止服务后[重置](05-backup-and-recovery.md#重置密码)。
- 密码错误次数过多：连续 5 次失败后等待 60 秒再试。
- 服务重启或会话失效：保留当前页面，通过“重新登录”恢复，不刷新未保存草稿。

管理命令与服务必须使用相同用户和 `MARKDOCK_DATA_DIR`。凭证文件 `.markdock-auth.json` 应为 0600；文件损坏时保留副本，优先恢复完整备份，不通过关闭认证解决。

## 目录不可访问

输入的是**服务所在设备的路径**。Docker 中应使用容器路径，例如 `/workspaces`，不是宿主机原路径。

检查目录是否存在、是否属于允许根、运行用户能否访问，以及路径中是否包含符号链接。不可访问的固定项可以重试或取消固定，不必删除真实目录。

没有“数据位置”时，核对 `MARKDOCK_WORKSPACE_ROOTS`。应用不自动发现容器挂载；环境变量更改后需要重启。

## 打开工作区缓慢或范围超限

进度面板显示当前阶段和真实计数。等待文件操作或执行恢复时，计数可能暂时不变；可取消的阶段会提供“取消打开”。

| 限制 | 用途 |
| --- | --- |
| 恢复检查：100,000 个条目、128 层 | 检查未完成文件操作 |
| 文档树：5,000 个条目、30 层 | 加载可浏览的文档范围 |
| 编辑历史预算 | 限制浏览器撤销记录，与扫描无关 |

打开检查跳过隐藏项和 node_modules，但其他未排除的条目仍可能计入。范围超限时选择更具体的文档目录；不要删除 `.noteai-operations/` 绕过恢复检查。

网络中断不能证明恢复已完成或已撤销。保留现场，按错误处理；不要反复自动发送打开请求。

## 保存失败与外部冲突

先保留页面，检查磁盘空间、挂载权限、目录同步和硬链接支持。同步失败时文件可能已更新，应核对磁盘后再重试。

外部编辑器、Git 或脚本可能产生冲突。避免同时写入同一文件，按[冲突处理](05-backup-and-recovery.md#保存失败与冲突)选择重新读取或另存副本。

## 图片或附件不可用

核对格式、大小及[工作区资源设置](03-configuration.md#工作区资源设置)。图片支持 PNG、JPEG、GIF、WebP、AVIF，单张 20 MiB；附件上传单个 100 MiB。

资源缺失时检查实际文件和 Markdown 地址是否一致，尤其是外部移动后的相对路径。当前及有效旧规则参与资源识别；资源接口不提供任意工作区文件访问。

资源列表分页失效时刷新列表；图片加载失败可重试或下载。SVG、HTML 等不会作为图片内嵌执行。撤销插图和取消上传不保证清理已经落盘的资源。

## 原文块或格式按钮与预期不同

不支持安全转换的语法显示为可编辑原文，并非只读或解析错误。可继续编辑或切换源码；重新进入可视化时会重新分析。

行内格式需要非空文字选区；代码、表格、原文块或混合选区可能限制命令。组字、上传、冲突和文件操作期间部分控件暂不可用。

## 移动、垃圾箱或恢复失败

目标已存在、资源归属冲突、外部修改或缺失资源都会阻止操作，应用不会覆盖或合并。先查看具体提示，保留相关文件和恢复记录。

垃圾箱恢复使用原路径。彻底删除失败可重试，不能通过手动删元数据消除提示。处理步骤见[备份与恢复](05-backup-and-recovery.md)。

## 远程访问或容器异常

核对浏览器地址、`MARKDOCK_PUBLIC_ORIGIN` 与代理传递的 Host 是否一致，包括端口。只传 `X-Forwarded-Host` 不足以通过校验。后端应处于私有网络或回环地址，不关闭认证或放宽来源检查。

查看容器日志：

```sh
docker compose --env-file .env.docker logs --tail=50 markdock
```

检查宿主机挂载存在、UID/GID 和 NAS ACL、剩余空间及文件系统能力。不要递归修改个人文稿所有权来掩盖权限问题。

打开进度停顿时还应检查代理超时和响应缓冲；健康检查通过仅代表进程响应。代理要求见[部署说明](01-deployment.md#https-反向代理)。

## 报告问题

附上运行方式、系统或容器环境、复现步骤和经过脱敏的错误信息。不要提供密码、Cookie、真实凭证文件或私人文稿。说明是否存在未保存内容，避免排查操作破坏现场。
