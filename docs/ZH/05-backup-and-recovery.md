# 05 · 备份与恢复

[English](../EN/05-backup-and-recovery.md) | **简体中文**

MarkDock 直接操作磁盘文件。自动保存、垃圾箱和操作恢复各有用途，不能替代独立备份。

## 需要备份什么

| 数据 | 位置 | 是否应备份 |
| --- | --- | --- |
| 固定工作区列表、密码哈希 | `MARKDOCK_DATA_DIR` | 是，保护凭证文件访问权限 |
| Markdown、图片、附件 | 工作区目录 | 是 |
| 资源规则 | 工作区 `.markdock.json` | 是 |
| 原文备份 | `.noteai-backups/` | 随工作区一起备份 |
| 垃圾箱 | `.noteai-trash/` | 随工作区一起备份 |
| 文件操作恢复记录 | `.noteai-operations/` | 随工作区一起备份，不能当缓存清理 |
| 界面偏好、写作目标 | 当前浏览器 | 不包含在服务备份中 |
| 撤销历史、未保存会话 | 页面内存 | 不随服务备份或重启恢复 |

## 制作一致的备份

1. 在页面确认所有文档保存成功，等待上传和文件操作结束。
2. 停止 MarkDock，停止其他编辑器或脚本向相关目录写入。
3. 复制完整服务配置目录及工作区目录，包含隐藏文件和子目录。
4. 将副本保存到独立存储，核对文件数量、权限和可读取性。

不要只复制 `.md` 文件，否则会遗漏资源、配置和恢复记录。凭证备份属于敏感数据。

## 保存失败与冲突

保存失败时先保留页面和草稿，检查磁盘空间、权限及挂载状态。**不要先刷新页面。**

出现外部修改冲突时，选择需要保留的版本：

- 重新读取：采用磁盘版本，会重建该文档会话。
- 另存副本：将本地内容保存为同目录副本，再人工核对差异。

“磁盘同步失败，操作结果尚未确认”表示文件可能已经更新。先核对磁盘与备份，不要把错误提示当作“完全没有写入”。

首次写回前的原文保存在 `.noteai-backups/`，不是每次编辑的完整历史。人工恢复前先另存当前文件，再核对所需备份。

## 从垃圾箱恢复

在侧栏打开“垃圾箱”，找到文档并选择恢复。文档与随行专属资源回到原路径；缺失父目录可重建，路径被占用则停止，不覆盖或合并。

其他文档若引用被删除文档的专属资源，资源在垃圾箱期间可能失效。共享资源不随文档删除。

彻底删除或清空垃圾箱只移除选定条目及随行资源，不清理独立历史备份。文件删除不属于正文撤销历史。

## 文件操作中断

重新打开原工作区时会检查未完成操作，并在条件允许时恢复。若提示外部修改、损坏记录或其他工作区存在未完成操作：

1. 停止对相关目录写入。
2. 完整备份现场，包括 `.noteai-operations/`。
3. 按错误提示回到原工作区处理；不能自行确认时保留现场排查。

不要删除恢复记录、改变允许范围或强行覆盖文件以绕过错误。多个文件不是一个原子文件系统事务，现有恢复机制不保证突然断电后所有操作都已持久保存。

## 重置密码

先停止服务。源码部署在相同配置目录和运行用户下执行：

```sh
bun run auth:password --reset
```

Docker 部署执行：

```sh
docker compose --env-file .env.docker stop
docker compose --env-file .env.docker run --rm --no-deps markdock node admin/auth-password.mjs --reset
docker compose --env-file .env.docker up -d
```

重置不会修改文档或固定列表；服务重启后需要重新登录。凭证文件损坏时不会被静默覆盖，见[登录故障](06-troubleshooting.md#登录失败或会话失效)。

<details>
<summary>无交互终端时设置密码</summary>

密码命令支持 `--password-file /绝对路径`，文件须为权限 0600 的普通文件，不能是符号链接。Docker 需要额外只读挂载，使用容器内路径。不要将明文密码放在命令参数、环境变量或镜像中；使用后妥善保管或移除输入文件。

</details>

## 升级与回滚

完成停机备份后，切换到计划使用的源码版本。

源码部署：

```sh
bun install --frozen-lockfile --ignore-scripts
bun run build
bun run start
```

Docker 部署：

```sh
docker compose --env-file .env.docker build
docker compose --env-file .env.docker up -d --force-recreate
```

登录后检查工作区、文档和资源是否正常。绑定挂载保存在宿主机，重建容器不会替代备份。

回滚时同时核对程序与数据格式，必要时恢复配套停机快照。当前没有通用的数据格式降级承诺；不要让新旧服务同时写同一数据目录。

## 旧资源整理

已有资源规则继续用于解析旧链接，通常不需要手工整理。需要显式整理时，先备份、停止并发写入，再在源码环境执行：

```sh
bun scripts/migrate-resources.ts /绝对工作区路径
```

这是预览。核对受影响文档后才执行：

```sh
bun scripts/migrate-resources.ts --apply /绝对工作区路径
```

工具保留旧资源与正文备份，遇到缺失、重名或不支持内容会报告；不会扫描历史工作区列表。该工具需要源码和 Bun，不包含在精简运行镜像中。
